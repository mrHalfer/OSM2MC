# Рутинные задачи — пошаговые рецепты

Часть инструкции `AGENTS.md`. Открывай рецепт под свою задачу
(номера рецептов 5.x — внутри этого файла). Версия, CHANGELOG и релиз — раздел
«Версия, журнал изменений, релиз» в `AGENTS.md`.

### 5.1. Изменить поведение экспортёра (блоки, формы, цвета)
1. Найди код: `grep -n "ключевое_слово" export/mcworldexporter.cpp`. Комментарии в коде английские — ищи по английским словам (`roof`, `window`, `entrance`…).
2. Прочитай **только** нужный участок (±60 строк). Посмотри, как соседний код решает похожую задачу, и повтори стиль.
3. Блок по имени: `quint16(IdPaletteStart + paletteIndexOf("minecraft:имя_блока"))`. Блока нет в палитре `kBlockPalette` — **допиши его в конец массива** (не в середину!) с RGB-цветом.
4. **`store.set(x,y,z, IdAir)` ничего не делает** (воздух игнорируется). Чтобы убрать блок — `store.erase(x,y,z)`.
5. Соберись, прогони тесты, посмотри результат на тестовой сцене (`.agents/build-test.md`).
6. Запиши изменение в `CHANGELOG.md` (раздел `AGENTS.md` «Версия, журнал изменений, релиз»).

### 5.2. Добавить или изменить правило OSM (`resources/osm_rules.json`)
- Формат описан в разделе `_help` самого файла. Правило: `from` (`points`/`lines`/`multipolygons`), `when` (условия по тегам), `layer`, `fields` (`CODE`, `REL`, `MAT`…).
- **Неоднозначное сопоставление с Minecraft — через вики, не через память:** если непонятно, какому биому/существу/блоку/ID в игре соответствует OSM-тег (пример: `natural=wetland` — это игровой болотный биом, но НЕ `minecraft:wetland`), сначала быстро изучи нужный раздел вики minecraft.wiki (названия и ID там должны совпадать с игрой буквально). Быстро не выясняется однозначно — **спроси у владельца**, что делать, и не выдумывай. См. `.agents/pitfalls.md` (идентификаторы игровых регистров, wetland/swamp).
- Порядок важен: срабатывает первое подходящее правило; частное ставь **выше** общего.
- После правки проверь JSON на валидность (`python -c "import json;json.load(open('resources/osm_rules.json',encoding='utf-8'))"`), прогони `py -3 run_tests.py osm`.
- Дополнительная проверка без построения мира: `osmc.exe файл.osm --dry-run --nogui --log run.log` — в логе будет счёт объектов по слоям.

### 5.3. Новая строка интерфейса (перевод)

> **Проверяй цикл перевода на ВСЕХ добавленных элементах:** после `lupdate` убедись, что перевод вписан на каждую новую строку проекта (не только на явно добавленные тобой — смотри `type="unfinished"` целиком), строки реально проходят через `tr()`/`translate` (синонимы в `QLabel` конструкторе без `tr` не переводятся), а контекст строки тот же, что и у соседних (например, названия зон — контекст `Climate`). Проверка: `Select-String 'unfinished' translations\osmc_ru.ts` пустой + `lrelease` прошёл + в живом окне на `--lang ru` текст русский.
1. В коде строки пишутся **по-английски** в `tr("...")` / `QObject::tr("...")` / `QCoreApplication::translate`.
2. Выполни: `lupdate osmc.pro -ts translations/osmc_ru.ts` (Qt: `C:\Qt\5.15.2\msvc2019_64\bin`, добавь в `PATH`). Старые переводы сохранятся, новые строки получат `type="unfinished"`.
3. Открой `translations/osmc_ru.ts`, найди пустые `<translation type="unfinished"></translation>` и впиши русский текст (сохраняя `%1`, `%2` и пунктуацию). Атрибут `type="unfinished"` удали.
4. Пересобери (`lrelease` запускается сборкой) и проверь, что `unfinished` не осталось: `Select-String 'unfinished' translations\osmc_ru.ts`.

### 5.4. Правка README / документации
- `README.ru.md` — оригинал владельца, **структуру и тон не меняй без просьбы**. `README.md` — его точный перевод на английский с той же структурой и заголовками.
- Любая правка в одном — зеркальная правка в другом.
- Картинки в README — относительные ссылки `images/...`.

### 5.5. Добавить скриншот в галерею
1. Скриншоты лежат в `images/screen/…` (в `.gitignore`, это исходники; возможны подпапки — `shots/4` и т.п.).
2. Обработай Pillow: открыть, `convert('RGB')` (PNG часто RGBA — JPEG его не принимает), **обрезать по центру до 2:1** (при `w ≥ 2h` срезай высоту, иначе ширину), `resize((1600,800), LANCZOS)`, сохранить JPEG `quality=86` как `images/shots/NN_имя.jpg`; превью `resize((400,200), LANCZOS)` — под тем же именем в `images/shots/thumbs/`. `NN` — следующий номер после существующих (смотри `Get-ChildItem images/shots`), имя — маленькими буквами через подчёркивание.
3. Добавь строку(и) ячеек в таблицу «Галерея» в **обоих** README (по 3 ячейки в ряду, `width="33%"`, подпись в `<sub>` и в `alt`; по-русски в `README.ru.md`, по-английски в `README.md`, структура ряд в ряд). Подписи пиши по фактическому содержимому кадра (посмотри картинку), а не по названию темы.
4. В `CHANGELOG.md`: строка «A gallery of screenshots … N pictures» живёт в старой секции — меняй `N` на месте; и добавь пункт в `[Unreleased]` → `Added` (галерея README — видимое пользователю изменение).

### 5.6. Иконка / картинки интерфейса
