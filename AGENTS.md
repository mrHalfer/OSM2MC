# Инструкции для ИИ-помощника (Qwen и любые другие агенты)

Этот файл — правила работы с проектом **OSMC** (экспортёр OpenStreetMap в мир Minecraft). Прочитай его целиком перед первой правкой, затем открой файлы в `.agents/` под свою задачу (таблица в разделе «Что читать когда»). Если что-то здесь противоречит твоим привычкам — прав этот файл или нужный файл в `.agents/`. Если задача выходит за описанное — остановись и спроси владельца, а не додумывай.

- Владелец: Denis Rakhmatullin (mrHalfer). Общайся с ним **по-русски**.
- Репозиторий: https://github.com/mrHalfer/OSM2MC (локальная папка называется `E:\Projects\tMC`).
- Проект: C++ / Qt 5.15.2 / GDAL 3.4, две платформы: Windows x64 (MSVC, qmake + nmake) и Linux x64 (gcc, qmake + make, релиз — AppImage; окружение сборки — `docs/porting-linux.md`).
- Пользовательская документация: `README.md` (английский) и `README.ru.md` (русский). Для разработчика: `DEVELOPING.md`. Журнал изменений: `CHANGELOG.md`.

## 1. Золотые правила (нарушать нельзя)

1. **Не делай `git commit`, `git push`, `git tag` и не создавай релизы, пока владелец не попросил.** Когда попросит — сообщение коммита пиши **на английском**, **без** строк `Co-Authored-By:` и без упоминания ИИ.
2. **Не открывай, не меняй и не упоминай в документации папку `private/`** (она в `.gitignore`): там личные материалы владельца, ничего оттуда не копируй в репозиторий.
3. **Никаких паролей, ключей, токенов, личных данных** в коде, документации, логах и коммитах. Единственная допустимая контактная информация — та, что уже есть в `LICENSE` и в `User-Agent`.
4. **Не удаляй и не перезаписывай файлы, не посмотрев на них.** Перед удалением и переименованием — спроси.
5. **Не меняй копирайт.** Держатель — «Denis Rakhmatullin (mrHalfer)». Название «EL-MODS MEDIA» держателем копирайта не является (оно оставлено в `QCoreApplication::setOrganizationName` только ради сохранённых настроек — не трогай).
6. **Не правь без прямого указания владельца:** `third_party/` (чужие библиотеки), `.git/`, готовые ресурсы `resources/*.dat` и `resources/templates/*.bin` (их изменение меняет мир целиком), `E:\Projects\QtWdfGit` (это другой проект).
7. **Не запускай и не убивай чужие процессы.** Исключение: `osmc.exe` перед линковкой — его можно закрыть (`Stop-Process -Name osmc -Force`), владелец это разрешил.

## 2. Как устроен проект (карта)

| Папка / файл | Что там |
|---|---|
| `app/` | Окно и точка входа: `main.cpp` (командная строка, окружение GDAL), `mainwindow.*`, онлайн-карта (`osmtilemap.*`, `osmonlinepanel.*`), загрузка OSM (`osmdownload.*`), язык (`i18n.*`), `tmcrun.*` — общий цикл экспорта |
| `input/` | `tmcproject.cpp` — чтение OSM/.tqt/shape через GDAL, применение правил, **здесь же обработка `building:part`, высот, крыш (`roof:*`)**; `t3dsettings.*` |
| `osm/` | `tmcosmrules.*` (правила из JSON), `tmcrel.*` (высоты), `tmcaddress.*`, `tmcgreen.cpp`, улучшайзер |
| `scene/` | `mcscene.*` — собирает объекты экспорта по слоям (поля слоя → свойства `McObject`); `modelbuilder.*` — сетки |
| `export/mcworldexporter.cpp/.h` | **Главный экспортёр мира (~16 000 строк).** Вокселизация, здания, интерьеры, дороги, деревья, структуры, запись чанков. Не читай целиком — ищи нужное через `grep`/поиск |
| `resources/` | `osm_rules.json` (правила тегов), `default.t3d` (3D-настройки), `heights.csv`, `*.dat` (готовые ресурсы, не менять), `templates/*.bin` (не трогать), `osmc.qss`, иконка `osmc.ico` |
| `translations/osmc_ru.ts` | Русский перевод интерфейса |
| `tests/` | Тесты (`tests/README.md`), `tests/data/osm_buildings.osm` — тестовая сцена |
| `images/` | Скриншоты для README (`online_*.png`, `data_*.png`, `shots/` — галерея 1600×800 + `shots/thumbs/` 400×200) |

Как идут данные: **OSM-теги → правила `osm_rules.json` → слои (`bldpol`, `vegpol`, `rdslin`…) с полями `CODE`, `REL` (высота), `MAT` (материал) и служебными (`MINH`, `ROOF…`, `PART`) → `scene/mcscene.cpp` превращает слои в `McObject` → `export/mcworldexporter.cpp` строит блоки`.

| Ситуация | Читать |
|---|---|

| Любая работа по логике мира: правила, блоки, цвета, здания, крыши, земля/дороги, растительность, точечные объекты, структуры, палитра блоков (`export/`, `input/`, `scene/`, `osm/`, `resources/osm_rules.json`) | `.agents/exporter.md` |
| Метро и рельсы: тоннели, залы вокзалов и вестибюли, входные шахты, canopy, линейные/одиночные станции, секретные комнаты | `.agents/metro.md` |
| Рецепты: новое поведение экспортёра, правило `osm_rules.json`, перевод интерфейса, README/галерея/скриншоты, иконка, новый файл проекта | `.agents/recipes.md` |

Если правишь порядок работы экспортёра или правил — обновляй знание в соответствующем
файле `.agents/`, а не написивай новые разделы прямо в `AGENTS.md` (он должен оставаться коротким входом).

## 4. Стиль кода

- Стиль **как у соседнего кода**: отступы 4 пробела, фигурные скобки на отдельной строке, названия в `camelCase`, константы `kName`. Подгони плотность комментариев под соседей.
- **Комментарии и строки интерфейса — по-английски.** В документацию и ответы владельцу — по-русски.
- Не добавляй зависимости, не меняй версии Qt/GDAL, не переписывай рабочее ради красоты.
- **GUI не протаскивай вниз**: в `core/`, `input/`, `osm/`, `scene/`, `export/` не добавляй include'ы `app/` и QtWidgets — эти слои должны оставаться собираемыми в headless-консольную серверную версию (принимает готовый `.osm`, без GUI и онлайна); при правке `app/tmcrun.cpp` держи его связь с GUI-кодом минимальной.
- Не оставляй отладочный код (`fprintf`, временные переменные окружения) в итоговой правке.
- Большие файлы: правь маленькими точечными заменами, а не переписывай целиком.
- Предупреждения компилятора вроде C4100/C4189 в старом коде не чини, если не просили.

## 5. Версия, журнал изменений, релиз

- **`CHANGELOG.md`** (английский, формат «Keep a Changelog»). Любое заметное для пользователя изменение — строка под `## [Unreleased]` в разделах `Added` / `Changed` / `Fixed`. Не нужно записывать чисто внутренние правки без видимого эффекта.
- **Версия** — строка `VERSION = ...` в `osmc.pro`, формат `1.2.YY.MMDDN`: `YY` — год, `MMDD` — месяц и день, `N` — номер сборки за день (1–9). Пример: `1.2.26.10283` — третья сборка 28 октября 2026. Меняй **только эту строку** (через замену строки, не переписывая файл). Увеличивать версию **только когда владелец просит собрать релиз.** Major/minor не трогай без прямой просьбы.
- После смены VERSION **обнови timestamp `app/exportmeta.cpp`** (`(Get-Item app\exportmeta.cpp).LastWriteTime = Get-Date`) и только потом собирай: версия передаётся в код через `-D` (DEFINES), а nmake из-за смены `-D` файл не перекомпилирует — в бинаре останется старая строка. Проверка: экспорт и `export_info.json` → `exporterVersion`.
- **Релиз — ОБЕ платформы, двумя скриптами** (версия в `osmc.pro` у них общая): Windows — `cmd /c "E:\Projects\tMC\make_release.bat"` → `E:\Builds\tMC\package\OSMC-<версия>-win64.zip`; Linux — `cmd /c "E:\Projects\tMC\make_release_linux.bat"` → туда же `OSMC-<версия>-x86_64.AppImage` и `OSMC-<версия>-linux64.tar.gz` (серверный). Для Linux нужен WSL-дистрибутив `Debian-11` (порог совместимости по glibc; порядок подготовки — `docs/porting-linux.md`; переменные `OSMC_WSL`, `OSMC_BUILD`, `OSMC_OUT`). Перед этим: тесты зелёные, секция `[Unreleased]` в `CHANGELOG.md` переименована в `[версия] — дата` (сверху новая пустая `[Unreleased]`).
- **Текст коммита** (когда попросят): на английском, первая строка в стиле `feat: ...` / `fix: ...`, дальше список пунктов. Без `Co-Authored-By`.

## 6. Как отвечать владельцу

1. Коротко и по делу, по-русски. Скажи, **что изменил** (файлы), **чем проверил** (сборка/тесты/просмотр) и **что не проверено** (например, «в игре не смотрел»).
2. Если тесты упали или результат не тот — так и скажи, не прячь.
3. Если правка неоднозначна (несколько способов, влияет на внешний вид мира) — предложи вариант и спроси, а не молча выбирай.
4. В конце — готовый текст коммита, **только если владелец просил**.
5. Ничего не коммить и не пушь без команды.
